One Name, Five Layers

Onboarding aaaaaaaa as an AWS and Nutanix administrator is one string carried through five systems. Each layer either creates a new name, reuses an existing one, or gates the handoff and a mismatch in any one of them breaks the chain.

The one rule

The LLDAP uid, the resolved JWT principal, and the OpenFGA user:<slug> must be the same string — and that string must earn non-empty scopes. A bare aaaaaaaa has no -owner/-admin/-viewer suffix, so principal_scopes() returns empty and the REST API answers auth_user_unknown before OpenFGA is ever consulted. Fix it by renaming with a role suffix, or by adding a principal_map.json entry.
