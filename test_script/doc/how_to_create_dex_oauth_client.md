# How to Create / Modify / Delete a Dex OAuth2 Client

This guide covers **static OAuth2 clients** in Dex (`../dex`): the
`staticClients` block in `config.yaml`, what a client means downstream, and
how to add, change, or remove one.

> **What a client is here.** A Dex `staticClients` entry is an OAuth2 client
> that Dex registers in-memory. The single seeded client is `libcloud-rest`
> — used by the libcloud REST API for the authorization-code flow **and** as
> the `aud` claim that OpenFGA validates on every JWT. Adding a second client
> is rare; most deployments keep exactly one first-party client so
> `skipApprovalScreen: true` stays safe.

---

## 0. The seeded client

```yaml
staticClients:
  - id: libcloud-rest
    name: libcloud REST API
    secret: <rendered from LIBCLOUD_OIDC_CLIENT_SECRET>
    redirectURIs:
      - http://127.0.0.1:8766/oauth/callback
      - http://localhost:8765/oauth/callback
```

- `id` → becomes the JWT `aud` claim. OpenFGA validates `aud=libcloud-rest`.
- `secret` → generated by `dex_bootstrap.py` (`secrets.token_urlsafe(32)`)
  unless `LIBCLOUD_OIDC_CLIENT_SECRET` is provided.
- `redirectURIs` → the libcloud REST API callback URLs.

The rendered `config.yaml` and `generated/dex.env` are emitted by
`../openfga_my/dex_bootstrap.py` — **do not edit `config.yaml` by hand**;
edit the template and re-run the bootstrap.

---

## 1. Prerequisites

- `../dex` and `../openfga_my` are checked out.
- `setup.sh` has run at least once (so `libcloud_net` exists and Dex is up).
- You can authenticate as `superadmin` (for downstream OpenFGA / Vault
  changes that a new client may require).

---

## 2. ADD a new OAuth2 client (e.g. `grafana`)

### Step 1 — Edit the template

Edit `../dex/config.template.yaml` and append a second entry under
`staticClients`:

```yaml
staticClients:
  - id: libcloud-rest
    name: libcloud REST API
    secret: __LIBCLOUD_REST_SECRET__          # placeholder if you ref it
    redirectURIs:
      - http://127.0.0.1:8766/oauth/callback
      - http://localhost:8765/oauth/callback
  - id: grafana
    name: Grafana
    secret: __GRAFANA_OIDC_CLIENT_SECRET__
    redirectURIs:
      - http://localhost:3000/login/generic
```

> If you add a new placeholder (`__GRAFANA_OIDC_CLIENT_SECRET__`), teach
> `../openfga_my/dex_bootstrap.py` how to resolve it (generate a random
> secret or read an env var) and where to write it in `generated/dex.env`.

### Step 2 — Re-render and recreate Dex

```bash
cd ../openfga_my
SUPERADMIN_JWT=<...> python3 dex_bootstrap.py          # re-renders config.yaml + dex.env
docker compose -f ../dex/docker-compose.yml up -d --force-recreate dex
```

### Step 3 — Update downstream consumers

| Consumer | Change |
|----------|--------|
| OpenFGA (`../openfga_my/docker-compose.yml`) | If the new client should also be an accepted `aud`, add it to `--authn-oidc-audience` (comma-separated). The seeded setup accepts only `libcloud-rest`. |
| New relying party (e.g. Grafana) | Point its OIDC config at `http://localhost:5556/dex` (host) / `http://dex:5556/dex` (in-cluster), client id + secret from `generated/dex.env`. |
| libcloud REST | Unchanged unless it should accept the new `aud`. |

---

## 3. MODIFY a client

### 3.1 Change a `redirectURI`

Edit `config.template.yaml`, re-run `dex_bootstrap.py`, then
`docker compose -f ../dex/docker-compose.yml up -d --force-recreate dex`.

### 3.2 Change the `secret` (rotation)

See [how_to_rotate_dex_preshared_key.md](how_to_rotate_dex_preshared_key.md).
The short version: re-run `dex_bootstrap.py` (with a new
`LIBCLOUD_OIDC_CLIENT_SECRET` if you want to pick the value), recreate Dex,
then update every consumer that caches the secret (`generated/dex.env`
readers, libcloud REST `.env`, OpenFGA compose).

---

## 4. DELETE a client

1. Remove the entry from `config.template.yaml`.
2. Remove any placeholder + `generated/dex.env` writer for it in
   `dex_bootstrap.py`.
3. Remove the client from OpenFGA `--authn-oidc-audience` if you added it.
4. Re-run `dex_bootstrap.py` and `up -d --force-recreate dex`.
5. Update / retire the relying party that used it.

Existing tokens minted for the deleted `aud` will start failing OpenFGA's
`aud` check immediately; in-flight browser flows are lost
(`storage.type: memory`).

---

## 5. VERIFY

```bash
# OIDC discovery (lists configured endpoints, not clients):
curl -s http://localhost:5556/dex/.well-known/openid-configuration | jq

# Perform a token exchange against the new client to confirm id+secret:
# (authorization-code flow via the relying party, or a direct client-credentials
#  test if you enabled that grant)

# Token validates at OpenFGA with the new aud:
LIBCLOUD_USER=<user> LIBCLOUD_PASSWORD=<pw> scripts/openfga-check.sh \
   user:<uid> can_connect libcloud_api:main
```

---

## 6. Files touched

| File | What changes |
|------|--------------|
| `../dex/config.template.yaml` | `staticClients` entry added / changed / removed |
| `../dex/config.yaml` | re-rendered (do not hand-edit) |
| `../openfga_my/dex_bootstrap.py` | new placeholder resolver + `generated/dex.env` writer |
| `generated/dex.env` | new client id / secret lines |
| `../openfga_my/docker-compose.yml` | `--authn-oidc-audience` if a new `aud` is accepted |
| consumer relying party | OIDC config pointing at Dex |
